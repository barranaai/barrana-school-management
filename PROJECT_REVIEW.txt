OVERALL HEALTH
--------------------------------------------------------------------------------

Functionally rich and feature-complete across four roles (super-admin, school
admin, teacher, parent): AI reporting, incident reporting, parent-teacher meetings,
messaging, PDF generation, calendar/events, multi-tenant by schoolId.

Engineering maturity is prototype-grade. The most serious problems are:
  1. Verified P0 security holes (disabled auth rate limiting, unauthenticated AI
     routes, path traversal, open CORS, debug endpoints).
  2. Cross-tenant data leaks in a multi-tenant SaaS (P1).
  3. Heavy technical debt: god components (2,000-3,800 line files), ~3,000+ lines
     of dead code, ~800 console.log calls, near-zero test coverage.

Newer modules (incidents, meetings) are noticeably better engineered and enforce
tenancy correctly — use them as the template for remediating older code.

================================================================================
1. CRITICAL SECURITY (P0) — FIX BEFORE ANY FURTHER DEPLOYMENT
================================================================================

1.1 Auth rate limiting DISABLED [STILL OPEN]
    backend/routes/auth.js:12-16
    `authLimiter` is a no-op that logs "Rate limiter bypassed for debugging" and
    calls next(). The real limiter (50/15min) is commented out at lines 18-27.
    Impact: unlimited brute-force against /login and /register.
    Fix: restore the real rateLimit() limiter.

1.2 ALL /api/ai/* routes are UNAUTHENTICATED
    backend/routes/ai.js:53, 121, 195, 305 (no `protect` middleware)
    Impact: anyone on the internet can call generate-report / transcription /
    file upload, burning OpenAI spend and uploading arbitrary files.
    Fix: add protect + authorize(...) to every AI route.

1.3 Path traversal + public file read [STILL OPEN]
    backend/routes/reports.js:670 AND 1583 (endpoint registered TWICE)
    GET /api/reports/test-media/:filename joins req.params.filename into a path
    with no sanitization and no auth. Combined with the public static mount
    (server.js:60), files under uploads/ are world-readable.
    Fix: delete the endpoint (and its duplicate), or sanitize (reject "/" and "..").

1.4 Debug / test endpoints live in production [STILL OPEN]
    - POST /api/auth/test-login  — bypasses middleware, logs credential metadata
      backend/routes/auth.js:508-545
    - GET  /api/auth/debug/users — unauthenticated user count   auth.js:480-487
    - GET  /api/auth/test        — public probe                 auth.js:470-477
    - POST /api/reports/test-temp-media / test-upload — public uploads
      reports.js:1626, 1665
    Fix: remove, or gate behind NODE_ENV !== 'production'.

1.5 CORS wide open
    backend/server.js:88-94 — origin: true + credentials: true reflects ANY origin.
    Impact: any website can make credentialed cross-origin requests.
    Fix: explicit allowlist (mirror the Socket.io whitelist in socketService.js).

1.6 Rate-limit skip precedence bug
    backend/server.js:76
      skip: (req) => NODE_ENV === 'development' && req.ip === '::1' || req.ip === '127.0.0.1'
    Parses as (dev && ::1) || 127.0.0.1, so 127.0.0.1 ALWAYS skips the limiter,
    even in production. Fix: wrap the OR in parentheses.

1.7 Open registration with privileged roles
    backend/routes/auth.js:32-38 — public /register accepts role:'school_admin'
    with no approval flow. Fix: restrict self-registration; require admin invite.

1.8 Helmet CSP disabled
    backend/server.js:63-65 — contentSecurityPolicy: false.
    Fix: enable a real CSP (relevant given frontend uses dangerouslySetInnerHTML).

1.9 MOBILE: hardcoded HTTP API + cleartext [STILL OPEN - relocated]
    BarranaMobileApp/apiService.ts:5-7 — http://191.101.233.56/api hardcoded for
    both __DEV__ and prod; no HTTPS. Android network_security_config.xml permits
    cleartext. Impact: tokens/PII in plaintext.
    Fix: EXPO_PUBLIC_API_URL env var + HTTPS.

1.10 MOBILE: login logs credentials [STILL OPEN - relocated]
    BarranaMobileApp/apiService.ts:226-249 — logs email, password length, full
    response body and token. Fix: strip all credential/token logging.

================================================================================
2. MULTI-TENANT ISOLATION (P1) — CROSS-SCHOOL DATA LEAKS
================================================================================

Most business-critical class of bug for a multi-tenant SaaS. A school_admin or
teacher can access another school's data in these places:

2.1 ?schoolId= query overrides tenant filter for non-super-admins
    backend/routes/reports.js:398-403
    backend/routes/reportTemplates.js:12-19
    Fix: ignore client-supplied schoolId unless req.user.role === 'super_admin'.

2.2 GET /api/events/:id has no schoolId check (PUT/DELETE do)
    backend/routes/events.js:132-149 (contrast events.js:395, 530)

2.3 Report media routes don't verify report.schoolId === req.user.schoolId
    backend/routes/reports.js:1706 (GET), 1846 (POST), 1891 (DELETE)

2.4 Logo upload/get/delete missing school-ownership check
    backend/routes/schools.js:520, 525, 546 (contrast branding PUT at 465-469)

2.5 report-approval-notification trusts schoolId from request body
    backend/routes/communication.js:14-28

2.6 authorizeSchool middleware EXISTS but is never wired to any route
    backend/middleware/auth.js:79-103 — ready-made tenant guard, unused.
